# AI Inference Gateway Relic Setup

This relic establishes a backend API gateway to unify access to various LLM providers (Google Gemini, Groq) and serves your custom ChimeraDash OpenRouter-style frontend.

## Prerequisites

*   Docker and Docker Compose (or Docker with Compose plugin) installed.
*   Your complete ChimeraDash "OpenRouter-style" frontend application source code.
*   API keys for the LLM providers you wish to use (e.g., Google Gemini, Groq).

## Setup Steps

1.  **Populate Frontend Code:**
    *   The directory `chimeradash_frontend_code/` has been created.
    *   **CRITICAL USER ACTION:** Delete any placeholder files inside `chimeradash_frontend_code/` (if any were generated by a previous plan iteration for this directory).
    *   Copy your **entire** ChimeraDash frontend project (including `package.json`, `vite.config.ts`, `tsconfig.json`, `index.html`, the `src/` directory, etc.) into the `chimeradash_frontend_code/` directory.
    *   The relic plan provides a `Dockerfile`, `nginx.conf`, and `vite-env.d.ts` inside `chimeradash_frontend_code/`. If your project already has these, compare and merge or use the relic's versions, ensuring they are compatible with a Vite build and Nginx serving.

2.  **Configure Environment Variables (`.env`):**
    *   An `.env` file has been created. Open it and update the following:
        *   `GEMINI_API_KEY`: Your API key for Google Gemini.
        *   `GROQ_API_KEY`: Your API key for Groq.
        *   (Add other keys as you integrate more providers).
        *   Review `BACKEND_PORT_HOST` (default `8002`) and `FRONTEND_PORT_HOST` (default `3002`) if they conflict with other services on your machine.
    *   The `API_GATEWAY_URL_FOR_FRONTEND` (e.g., `http://ai-inference-gateway-backend-api:8000`) is used to set the `VITE_API_GATEWAY_URL` environment variable inside the frontend Docker container. Your frontend application **must** use `import.meta.env.VITE_API_GATEWAY_URL` to make API calls to this gateway.

3.  **Build and Start Services:**
    *   Open your terminal in the root directory of this `ai-inference-gateway` relic.
    *   Run: `make up` (or `make rere` for a clean rebuild without cache).
    *   This command builds Docker images for the backend API gateway and your frontend, then starts them.

4.  **Access Your ChimeraDash Frontend:**
    *   Open your web browser and navigate to `http://localhost:3002` (or the `FRONTEND_PORT_HOST` you set in `.env`).
    *   Your ChimeraDash frontend should load and be able to make API calls to the gateway at the path specified by `VITE_API_GATEWAY_URL` (e.g., `/v1/chat/completions`).

5.  **Test the Gateway API (Optional):**
    *   The API gateway itself is accessible on `http://localhost:8002` (or your `BACKEND_PORT_HOST`).
    *   Context: `curl http://localhost:8002/context | jq`
    *   Available Models: `curl http://localhost:8002/api/v1/config | jq`
    *   Use the client script for more comprehensive tests (after setting API keys in `.env`):
        ```bash
        chmod +x scripts/ai_gateway_client.sh
        ./scripts/ai_gateway_client.sh
        ```

6.  **Development & Guidelines:**
    *   Consult `GUIDELINES.md` for details on the project structure, how to add more LLM providers, and other development notes.

If frontend build issues occur, ensure your `package.json` in `chimeradash_frontend_code/` is correct, all dependencies are listed, and the `build` script successfully outputs to a `dist/` folder.
